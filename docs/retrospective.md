One thing that went well during this project was seeing the website actually come together from the planning stage to a working website. At the beginning, I was still learning how all of the different files worked together, especially HTML, CSS, GitHub, and GitHub Pages. As I continued working on the project, I became more comfortable making changes, testing them, and organizing everything in the repository.

I am especially proud that I was able to create two connected pages and use one external CSS file to keep the design consistent. I also learned how important project planning and documentation are. Creating the scope and project plan before finishing the website helped me understand what I was actually trying to accomplish instead of just adding things without a clear purpose.

## What Went Wrong

The biggest challenge for me was troubleshooting. There were times when I made a change and expected something to work, but it did not look or behave the way I expected. Small things such as file names, navigation links, CSS, and organizing files correctly became more important than I originally thought.

I also realized that managing the project itself can be just as challenging as building the website. I had to make sure my files were in the correct locations, my documentation matched the project, and my website continued working after changes were made. This taught me that testing throughout a project is much easier than waiting until the end to check everything.

## What I Would Do Differently

If I were starting this project again, I would organize everything from the beginning and create a clearer checklist for each requirement. I would also test the website after every major change instead of making several changes before checking it. This would make troubleshooting easier because I would know exactly which change caused a problem.

I would also spend more time planning the design before writing the code. Now that I understand HTML, CSS, GitHub, and GitHub Pages better, I think I could work more efficiently and make the website more detailed. This project showed me that good project management is not only about finishing the final product. It is also about planning the work, managing risks, testing the results, documenting changes, and learning from problems along the way.

## Lessons for Future Projects

The biggest lesson I will take from this project is to stay organized and not rush through the planning process. Breaking a large project into smaller tasks made it easier to understand what needed to be completed. I also learned that mistakes are part of the development process, but documenting, testing, and correcting those mistakes makes the final project stronger.

For future projects, I will create a clear scope first, break the work into smaller tasks, identify possible risks, test throughout development, and keep my documentation updated as the project changes.
